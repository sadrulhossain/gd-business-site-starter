# Decisions

Log of architecture decisions. Format: `## NNN — Title` / Date / Decision / Why.

## 001 — phpredis, not Predis (superseded by 010)
2026-11-12. Use the phpredis extension (PECL redis 6.3.0). It compiles on PHP 8.5.12-fpm-alpine and loads; ACL user auth works through Laravel's `REDIS_USERNAME`/`REDIS_PASSWORD`. Predis is not installed.

## 002 — JSON error format
2026-11-12. Every exception renders as `{"error": {"code", "message", "details"?}}` via `App\Exceptions\JsonErrorRenderer`; `shouldRenderJsonWhen` is always true (API-only app). 5xx messages are hidden unless `APP_DEBUG`.

## 003 — API-only Laravel
2026-11-12. Skeleton web route, `/up`, welcome view, npm/Vite files and the skeleton's own CLAUDE.md/AGENTS.md were removed. Routes live in `routes/api.php` under `/api/v1`. Scramble serves docs at `/docs/api` (local env only).

## 004 — Tests use the compose services
2026-11-12. Pest runs inside the php container against the real Postgres/Redis from the container env (phpunit.xml forces cache/session to array, queue to sync). Health tests therefore need the stack up.

## 005 — Login flow: Authorization Code + PKCE (Passport 13) (superseded by 012)
2026-11-12. The admin SPA signs in with OAuth2 Authorization Code + PKCE (S256), no client secret.
- Client: public, fixed id `OAUTH_ADMIN_CLIENT_ID`, seeded by `OauthClientSeeder`; redirect `OAUTH_ADMIN_REDIRECT_URI`.
- First-party client skips consent (`App\Models\OAuthClient::skipsAuthorization`). Password grant stays off.
- Flow: SPA -> `api.*/oauth/authorize` -> API login page (session guard `web`) -> redirect with code
  -> SPA POST `/oauth/token` (code + verifier) -> access token (1h) + refresh token (30d)
  -> `Authorization: Bearer` on `/api/v1/*` (guard `api`).
- Built in phase 8 (see 011): the API login page for `/oauth/authorize` (session guard `web`, `GET/POST /login`).
- Keys: `storage/oauth-*.key`, generated by `fpm-start.sh`, git-ignored.

## 006 — Authorization model
2026-11-12. Spatie roles/permissions live on guard `api` (`User::$guard_name`, default guard `api`). Routes use
`->middleware('can:<permission>')`; `Gate::before` lets role `superadmin` through. Menus: `menus` table with an added
`title` column; a group row (no permission) shows only with a visible child. Tests refresh `<POSTGRES_DB>_testing`, never the dev DB.

## 007 — Content modules: edit-only, files on a volume
2026-11-12. Settings (one row, DB check `id = 1`) and Sections (seeded, immutable `key`) have no create/delete;
the portal renders by section key. Bilingual text uses `x` + `x_2nd` (`locales.second` = first supported locale
that is not the default). Uploads: disk root `UPLOADS_CONTAINER_PATH` (named volume `uploads-data`, shared by
php, php-queue, nginx), path `<dir>/<random>/original.<ext>`, extension from detected mime, WebP variants by a
queued job (GD). php-queue and php-scheduler run as `www-data` so files stay writable. nginx serves `/uploads/` static-only.
Tests: phpunit.xml `<env>` does not beat compose env, so `tests/bootstrap.php` forces the test environment.

## 008 - phpseclib 4.0.3 overrides Passport's 4.0.1 pin
2026-11-12. `laravel/passport` 13.11.0 (latest 13.x) requires `phpseclib/phpseclib` exactly 4.0.1, which has advisory
PKSA-h7cz-q7zq-mdkt (CPU-exhaustion DoS when parsing encrypted keys/PFX/CMS; fixed in 4.0.3). `api/composer.json` requires
`"phpseclib/phpseclib": "4.0.3 as 4.0.1"` (inline alias) so Passport's constraint is satisfied. Full test suite passes, `composer audit` clean.
Revisit when Passport releases a version that allows phpseclib >=4.0.3; then drop the alias and require plain `4.0.3`.

## 009 - Frontend: one pnpm workspace, source-only packages
2026-11-12. Root package.json + pnpm-workspace.yaml (`web/*`, `packages/*`) with a single `pnpm-lock.yaml`; shared versions live in the
workspace `catalog:` so react/react-dom/tailwindcss/typescript resolve once. pnpm runs via corepack (`packageManager`). Packages export
TypeScript/CSS source (no build step): Next and Vite compile them. `@gd/tokens` is Tailwind 4 `@theme` CSS, one file per app
(`admin.css`, `portal.css`, both on `base.css`); each theme resets `--color-*` so only its own palette exists. `@gd/api-types` is
generated from `packages/api-types/openapi.json` (`pnpm generate:types`, committed output). `@gd/api-client` is a dependency-free typed
fetch: Scramble documents updates as PUT while the API takes PATCH, so `patch` reuses the `put` types. Re-export the spec with `make
openapi` after migrating the dev DB (Scramble reads column types from it; without migrations every field degrades to `string`).
The node container mounts the repo at /app with named volumes over every node_modules; `make web` installs, regenerates types,
typechecks and builds both apps with NODE_ENV=production (Next prerender breaks under NODE_ENV=development).
## 010 - MariaDB, no Redis (superseded by 012)
2026-11-12. PostgreSQL is replaced by MariaDB 11.8.9 (LTS) using Laravel's `mariadb` driver and the `pdo_mysql` extension. Redis and phpredis are
removed: cache, sessions and queue use the `database` drivers (tables from the stock cache/jobs/sessions migrations). Consequences: queue
latency is polling-based (`queue:work --sleep=3`), cache locks and the rate limiter live in the `cache`/`cache_locks` tables, and the health
check reports `database` and `cache` (the `redis` key is gone). The test database is `<MARIADB_DATABASE>_testing`, created by
`scripts/ensure-test-db.sh`. Revisit if queue throughput or cache load outgrows the database; Valkey/Redis can come back behind the same Laravel drivers.

## 011 - Admin SPA: same-origin proxy, silent SSO, memory-only tokens (superseded by 012)
2026-11-13. The admin origin (nginx) proxies `/api/*` and `/oauth/token` to the API, so the SPA is same-origin with both and needs no CORS;
only the browser pages (`/oauth/authorize`, `/login`, `/logout`) live on the `api.*` origin. Passport's guard is `web` (a session login page,
`LoginController`, `throttle:login`); authorize with a non-first-party client is refused (403). Tokens live only in the Zustand store (never
local/sessionStorage; only the PKCE verifier and state cross the redirect, in sessionStorage). A reload therefore starts anonymous and the
route guard re-runs the authorize redirect, which the API's session cookie completes without a prompt (silent SSO). Refresh is single-flight
(`refreshTokens`), and the api-client retries a 401 once via `onUnauthorized`; a refused refresh clears the session, which sends the guard back to sign-in.
Sign-out: `POST /v1/logout` revokes the access and refresh tokens, then the browser goes to `GET /logout` on the API (ends the session) and
returns to `/signed-out`. Modules are config (`web/admin/src/modules.ts` -> `CrudPage`). Gaps: the sidebar has no icons; menu rows whose screen is
not built yet (posts, messages, settings) land on the 404 page. Browser tests run in the `e2e` compose service (official Playwright image,
profile `e2e`), not in the node container: Alpine's Chromium would not install reliably here.

## 012 - MERN on Cloudflare free tier
2026-11-17. Decisions: D1 branch `mern-cloudflare`; Laravel code moves to `legacy-api/` as read-only reference until M10. D2 Express 5 on a Worker
(`nodejs_compat`); Hono only if the CPU spike forces it. D3 static portal (Next export), rebuilt on a debounce; no server rendering. D4 email+password
login, 15-minute JWT in memory, rotating refresh token in a host-only httpOnly cookie; OAuth/PKCE is removed. D5 GitHub Actions builds the portal and
admin and deploys ONE Worker with wrangler; no Cloudflare build minutes. D6 keep the REST contract, `x` / `x_2nd` bilingual fields and numeric ids
(atomic `counters` collection). D7 WebP variants are produced in the admin browser; the raw original is never stored. D8 one Worker, one origin: portal
at `/`, admin at `/admin/`, API at `/api/*`, images at `/media/*`; free workers.dev address, custom domain optional later by configuration only.
D9 uploaded images live in `media/` at the repository root; the API commits them through the GitHub API and the deploy publishes them as static assets.
No R2, no object store.
Operating rules: no server rendering; `run_worker_first` is only the path list `/api/*`, `/admin/*` and `!/admin/assets/*` (never true); portal and admin
builds run on GitHub Actions; at most 3 of the 5 free cron triggers; weekly mongodump, encrypted before upload, kept as a GitHub Actions artifact
(artifacts of a public repository are readable by anyone); Atlas touched daily; `media/` is capped by file size (5 MB upload) and file count
(6,000 files; Cloudflare allows 20,000 per version).

## 013 - HTML sanitiser: sanitize-html
2026-11-17 (spike b, docs/SPIKES.md). sanitize-html 2.18.2 with the legacy allowlist (tags, `a[href|title|target]`, `img[src|alt|width|height]`, schemes http/https/mailto/tel, images http/https only, no protocol-relative URLs). It passed 35/35 hostile payloads and 10/10 allowed checks inside workerd. DOMPurify with linkedom was rejected because DOMPurify silently returns unsanitised input there; xss was rejected as a tokenizer, not a parser. Sanitise on write (never trust the editor) and keep the corpus as a permanent test.

## 014 - OpenAPI from zod: @asteasolutions/zod-to-openapi
2026-11-17 (spike c). Request and response schemas are zod 4 schemas; @asteasolutions/zod-to-openapi 9.1.0 generates the OpenAPI 3.1 document and reproduced two legacy schemas exactly. The zod built-in JSON Schema output differs in nullable, integer and date-time shapes. Deliberate differences from `docs/legacy-openapi.json` are logged in the M5 parity check.

## 015 - Rate limiting: Mongo TTL counters
2026-11-17 (spike f). The Workers Rate Limiting binding is approximate and per location, and the docs do not confirm it for the Free plan; WAF rate limiting needs a zone, and `workers.dev` has none. Login and contact use a fixed-window counter in a `rate_limits` collection (`_id` = route + hashed IP, or hashed email for login; `$inc` upsert; TTL index on `expiresAt`). One Mongo write per limited request. Revisit the binding after a deployed check.

## 016 - Auth: short JWT + rotating refresh cookie; PBKDF2 for now
2026-11-17 (Phase M2, implements D4). Access token: HS256 via jose, 15 minutes, claims sub/iat/exp/jti, no permissions inside (loaded with one aggregate per request). Refresh token: 32 random bytes, stored as HMAC-SHA256 keyed by `REFRESH_TOKEN_PEPPER`, rotated on every use with a family id; presenting a used token again revokes the family. The cookie is host-only, HttpOnly, Secure, SameSite=Lax; `/auth/refresh` and `/logout` also require `X-Requested-With: gd-admin` and a trusted Origin. `/logout` is public by design because the access token may have expired; the cookie identifies the family. A password change (own or by an admin) revokes all refresh tokens. Password hashes are self-describing (`$pbkdf2-sha256$i=<n>$salt$hash`) and rehashed on login when outdated. **Provisional:** PBKDF2-SHA256 at 100,000 iterations (the workerd cap) until spike a measures bcryptjs, argon2id WASM and PBKDF2 on a deployed free Worker (10 ms CPU limit). Revisit before M9; changing the algorithm needs no migration.

## 017 - Media: browser-made WebP variants committed through the GitHub API
2026-11-18 (Phase M3). Workers cannot run image libraries within the free CPU limit, so the browser resizes and encodes the variants and the Worker only validates and stores them. Each part is checked by magic bytes and its WebP header (width, height, 36,000,000 pixel cap); the raw original is never stored. All parts of one upload go into one commit through the Git Data API (blobs, tree, commit, fast-forward ref update, 3 retries when the branch moved). Old files are removed in a second commit after the document is saved, best effort. Known limit: a failed removal leaves orphan files until a cleanup is added; the file-count cap is counted from documents, so orphans are not counted. Not tested against real GitHub (no token in development).

## 018 - Contact notifications: pluggable adapter, default none
2026-11-18 (Phase M5). Cloudflare Workers cannot send SMTP on the free plan, and a custom sender domain is not assumed. The notifier is one interface (`send(to, message)`) with three adapters chosen by MAIL_PROVIDER: **none** (default; the message is stored and shown in the admin inbox with an unread count), **webhook** (POST to NOTIFY_WEBHOOK_URL, a secret, e.g. a chat service's incoming webhook; the body carries text/content plus the fields) and **http** (an email provider's JSON API, Resend-style; MAIL_FROM_ADDRESS must be an address the provider accepts without a domain of ours). It runs inside ctx.waitUntil after the message is stored, so a failure never fails the request; the log line carries only the adapter name and HTTP status, never the URL, key or body. Recipient: the Settings email, else CONTACT_NOTIFY_TO. Choice for this client: **none** until the client names a channel; switching is a variable change, not a deploy of new code. The webhook adapter has not been run against a real chat service and the http adapter not against a real provider (no credentials in development); both are covered by mocked-fetch tests.

## 019 - Publish pipeline: dirty flag, debounce, compare-and-set
2026-11-18 (Phase M5). Public content changes mark `site_state` dirty (markDirty, M3). A cron every 15 minutes dispatches the build workflow (GitHub REST workflow_dispatch) when the site is dirty, quiet for PUBLISH_QUIET_MINUTES (2) and no dispatch happened within PUBLISH_DEBOUNCE_MINUTES (5). After the dispatch it stores last_dispatched_at and clears dirty_at only if it still equals the value read before dispatching, so a change made during the dispatch keeps the site dirty. The same run marks 'posts' dirty when a scheduled post's published_at passed since the previous run (last_run_at). POST /site/publish dispatches at once (one per minute for the whole site, permission site.publish); GET /site/status reports {dirty, last_dispatched_at}. Two overlapping runs can dispatch twice; the build is idempotent, so this is accepted. A daily run pings Atlas (the free cluster pauses after inactivity) and deletes what the TTL monitor has not yet removed. Not exercised against real GitHub Actions: the deploy workflow arrives with M8/M9.

## 020 - Portal as a static export: locale trees, per-page CSP, placeholders
2026-11-18 (Phase M7). The portal is `output: 'export'` with `trailingSlash: true`. A static export cannot rewrite, so both language trees are generated under `app/[locale]` and `scripts/finalize-export.mjs` moves the default tree to the root, writes `_redirects.portal` (`/<default>/*` to `/*`, 301) and deletes the prefixed copy, so each page has one URL. Canonical, hreflang, sitemap and links all use `localePath()`, which returns the final URL with its trailing slash. Blog lists are paths (`/blog/page/2/`, `/blog/category/<slug>/page/2/`) built from the API's `last_page`. Dynamic routes use `generateStaticParams` with `dynamicParams = false`; because an export fails on an empty list, a route with nothing to generate gets a placeholder param (`_none`, page `0`) that the finalize step deletes. **CSP:** Next's inline bootstrap scripts differ per page and a Cloudflare `_headers` line is limited to 2000 characters, so a header with every hash cannot work. Each page gets a `<meta http-equiv="Content-Security-Policy">` with `default-src 'self'; script-src 'self' <that page's sha256 hashes>`, and the header (`public/_headers.portal`) carries the other directives without `default-src`/`script-src` (both policies apply, so a header `script-src` would block the hashed scripts). No `unsafe-inline` for scripts. `frame-ancestors` cannot be set by meta, which is why it stays in the header. The 404 page is the `404-source` route rendered inside the locale layout and copied to `out/404.html`. Build-time fetches use `BUILD_API_URL` with 3 attempts and fail the build otherwise, so a broken API never publishes an empty site. Not run against the real Worker in this phase except by building once against the local dev API.

## 021 - Delivery: one assembled asset folder, one deploy workflow
2026-11-18 (Phase M8, implements D5 and D8). `scripts/assemble-site.mjs` builds `dist/site/` from the portal export, the admin build (under `/admin/`) and `media/`, and merges the per-app `_headers.portal`, `_headers.admin` and `_redirects.portal` into ONE `_headers` and ONE `_redirects` (Cloudflare reads only those names). `_headers` has no "everything except" rule, so the portal's `/*` block is expanded to the portal's own top-level paths; `/_next/*` carries no Cache-Control of its own, because two rules setting it would be joined with a comma. The build fails on a duplicate rule, a header set twice for one URL, or above 80 percent of a Cloudflare limit (100 header rules, 2,000 + 100 redirects, 20,000 files, 25 MiB per file). The Worker (`wrangler.jsonc` at the root; `api/wrangler.jsonc` stays the development config) handles only `/api/*` and `/admin/*` except `/admin/assets/*`; for `/admin/*` it serves the asset, or the admin index when the path has no file extension (`api/src/assets.ts`), only when the `ASSETS` binding exists. `deploy.yml` runs on `main` (ignoring `media/**`, `docs/**` and Markdown) and on dispatch; `bootstrap` deploys the admin and a placeholder so the API exists before the first portal build; `SITE_ORIGIN` and `LOCALE_*` are read from `wrangler.jsonc`, so there is no GitHub variable. Actions are pinned to commit SHAs. Nothing was deployed from this repository by Claude; every account step is a numbered manual step in `docs/DEPLOY.md`. Open: the Free plan's 10 ms CPU limit against PBKDF2 login, Atlas region latency, concurrent media commits and the `/admin/*` fallback are untested until Part D of DEPLOY.md is run (spikes a, e, g, h).
